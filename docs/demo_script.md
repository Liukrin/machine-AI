# 演示录屏脚本（2–3 分钟）

---

## 第一段：定位与架构（0:00–0:30）

**屏幕内容**：README 顶部标题 + mermaid 架构图（六层从左到右展开）。

**口播**：
"这是一个基于时序基础模型的液压系统故障检测平台。整个流程分为六层：从多传感器数据管道开始，Chronos-Bolt 对健康波形做零样本延拓生成置信带，确定性 Python 规则做偏离量化与告警分级——注意，告警分级完全不经过大模型。RAG 检索层从 12 条知识库中拉取匹配的维修条目，LangGraph 三节点闭环自动生成维护工单。最后，引用校验和严重度审计确保 LLM 输出可追溯。"

---

## 第二段：Streamlit Demo 实操（0:30–1:30）

**屏幕内容**：Streamlit 界面，左侧侧边栏切换窗口类型和工况，主区显示 Plotly 交互图。

**操作**：
1. 侧边栏选择"故障注入 (A)"，选一个 X 工况，拖动 cycle 序号
2. 鼠标指向图表：灰色线是 context 尾部（过去 60 秒），蓝色半透明带是 Chronos 预测的 q10–q90 置信带，红色线是实际波形
3. 红色 X 标记标注越界点，右上角红色徽章显示"DANGER"
4. 切到"近距健康对照 (B)"，绿色"正常"徽章
5. 再切到"远距健康对照 (C)"，部分窗口被判危险但远少于 A

**口播**：
"左侧可以切换三类窗口——故障注入、同一健康块内的近距对照、以及跨不同健康块的远距对照。蓝色半透明区域是 Chronos 预测的 80% 置信带，红色点是实际值超出置信带的位置。这个窗口被正确判定为危险。切换到近距健康窗口，同一工况下的健康波形完全落在置信带内，绿色正常。远距健康窗口有时也会被误判，误报率约 6.7%。"

---

## 第三段：LangGraph 诊断闭环（1:30–2:15）

**屏幕内容**：终端输出 LangGraph 场景运行结果，重点展示场景 D。

**操作**：
1. 展示场景 A（danger）的输出：检索命中 cooler-02，DeepSeek 生成工单
2. 展示场景 B（normal）的输出：Watcher→END，状态 completed，零 LLM 调用
3. **重点展示场景 D（齿轮箱）**：
   - 输入 `component="齿轮箱"`，alert_level=danger
   - 诊断路径：Watcher(skipped)→Diagnostician→END(rejected)
   - 输出：`hit=False`，reason="该组件「齿轮箱」无知识库条目"
   - LLM called: False

**口播**：
"告警触发后 LangGraph 三节点闭环自动运行。正常的窗口在 Watcher 节点直接结束——不调用大模型，零 token 消耗。重点是拒答场景：如果传入一个知识库中没有的组件，比如齿轮箱，诊断节点在闸一就直接拒绝，不进入向量检索，也不调用大模型。工单结论写'知识库无对应条目，需人工介入'。这是安全红线——不知道就是不知道，不编造。"

## 第四段：诚实性声明（2:15–3:00）

**屏幕内容**：README 中的三方对照表和 valve 五轮总表。

**操作**：
1. 高亮三方对照表三行完全相同的数字
2. 高亮 valve 五轮全部 0.00 的检出率

**口播**：
"最后是诚实性声明。cooler 组件上 Chronos 的检出率、误报率跟最简单的平凡均值法完全一致——不是模型不好，是故障信号太强，均值已经够了。valve 上五轮实验全部检出率为零——不是因为没努力换方法，而是泵和蓄能器的状态变化覆盖了阀门的故障信号，单通道物理上分离不出来。整个项目的实验记录、知识库数字审计脚本、过程失败日志全部开源在仓库里。没有美化，没有省略。"
