# 过程记录与失败日志

按时间顺序记录手册 RAG 管线（S1–S5）各阶段以及后续评测工作中的关键失败点、现象与教训。

---

| # | 阶段 | 失败点 | 现象 | 教训 |
|---|---|---|---|---|
| 1 | S3 | 全局 rerank 精排净亏 | 混合检索后接 CrossEncoder 精排：hard R@10 0.60→0.80、table R@10 0.714→0.857，但总体 R@1 0.778→0.639，7 条混合已排第 1 的正文题被降权，单题 +3.07s | 精排是「语义重排」不是「全局提升」，text 占多数的语料全局 rerank 净亏，应按难度/类型选择性启用而非一刀切 |
| 2 | S3 | 数字密集表结构性检索失败 | qa_038「泵轴对应部件编号」gold=4_c0310 在基线/混合/rerank 三路均未命中 top-10，问题与表格文本语义+字面重叠都极低 | 纯编号/零件表是 embedding 与 BM25 的共同盲区，需表格结构化解析或字段级索引 |
| 3 | S3 | 评测集答案跨块 | qa_001「同心度允差」的答案落在相邻 chunk 1_c0030（"不同心度允差0.1mm"）而非原 gold 1_c0029（"校正水平不平度<0.1mm"） | chunk 重叠 + heading 分组会使语义答案落在相邻块，评测须支持 gold_alt 多目标兜底 |
| 4 | S4 | 拒答阈值正负样本重叠 | 负样本「挖掘机液压泵」distance 0.3347 < 正样本 P95 0.3567，语义邻近查询穿过单一距离闸 | 语义邻近查询与正样本无清晰间隔，单一距离闸挡不住；按正样本 P95 取 τ=0.3567 并如实记录重叠 |
| 5 | S4 | 引用校验切句 bug | LLM 把 [chunk_id] 标在句末标点之后（…0.05mm。[2_c0016]），按「。！？」切句时引用被切到下一碎片，主句被误判为无引用 | 切句前先把紧跟句末标点之后的 [chunk_id] 移到标点之前（_move_citations_before_punct） |
| 6 | S5 | SSE 行尾 CRLF 不兼容 | sse-starlette 用 \r\n 分隔事件，前端按 \n\n 切事件，CRLF 流中无 \n\n，事件积压到流末一次性派发，只渲染出残缺 done 行、拒答路径崩溃 | SSE 事件边界解析须兼容 \r\n/\n/\r 三种行尾（用 /\r?\n\r?\n/ 切分），别硬编码 \n\n |
| 7 | S5 | 校验告警难自然触发 | temp=0 强 grounding 下 LLM 照抄检索原文，11 个探测问题多数 suspicious=0、fabricated_ids=[]，「泵的效率与扬程是什么关系」才触发可疑 2 句 | 校验告警是安全兜底分支，正常 grounded 生成下少见属预期；验收须专门构造脱离语料的问题 |
| 8 | S4 | 文档与代码脱节 | README 写「线上默认已切到 C 组提示词」，代码里仍是 B 组；写「embedding 与 LLM 均本地离线加载」，实际生成调用 DeepSeek API；拿来演示拒答的「挖掘机液压泵」恰是会穿过拒答闸的负样本 | 线上参数集中到 config（提示词存成文件、按版本 key 选择），服务与评测读同一批文件；文档里的每条说法都要对照代码和实测数字核对 |
| 9 | S5 | 误判答案被截断 | 排查时只打印答案前 400 字，看到「防爆泵」答案停在「引用 chunk_id: [」就认定是 max_tokens=500 截断；核对全文，实为 418 字的完整答案 | 下结论前看原始数据全文；是否截断以接口返回的 finish_reason 为准，已透传到前端与性能报告 |
| 10 | S5 | max_tokens 从未生效 | 为验证截断提示把上限临时改成 20，回答仍完整输出；查请求体发现 langchain-openai 1.6.0 把 max_tokens 改名为 max_completion_tokens 发出。直连 DeepSeek 实测：max_tokens=20 → finish_reason=length、输出 20 token；max_completion_tokens=20 → stop、输出 135 token。按 langchain-openai 1.6.0 的安装时间（08-25）推断，此前 API、命令行与两份评测报告（08-31 性能、09-01 引用对照）里的 max_tokens=500 都没有生效。旧性能报告实测输出最长 353 token，没触及 500，数字不受影响；引用对照实验三组同样没有上限，组间比较仍成立，但报告头的 max_tokens=500 不是实际生效值（已在报告中注明） | 生成上限经 extra_body 以 DeepSeek 认的 max_tokens 字段发送（llm_config.max_tokens_body）；配置是否真的生效，要用极端值实测，不能只看代码里传了参数 |
| 11 | 评测 | 忠实度满分但答错了对象 | 答案级评测里评审模型把几乎所有句子判为有依据，其中「减速机齿轮箱多久换油」被用泵手册的换油周期作答、「D型泵要不要放水」被用 Wilo 手册作答——句子相对检索片段确实有依据，只是对象不对 | 忠实度只衡量「句子有没有片段支持」，不等于答对；要另外看引用的片段是不是出自被问到的那份手册、那种设备 |
| 12 | 评测 | 评测脚本把引用算丢了 | 模型把引用写在句号后且不带括号（「…旋转。1_c0004」），沿用 verify.py 的切句会把这句话记为无引用（dev 19/105 句）；修正时把引用挪到句号前，又和前面的数字连成了错误的 id（「…2～32_c0042」） | 引用的写法不止一种，解析规则要用真实输出逐条核对；挪动文本片段时要留分隔符。评分逻辑的每条规则都加了自检，评测前先跑 |
| 13 | 评测 | 评审模型原样重试无效 | 评审输出的句数与给定的对不上（句子里的「1. …；2. …」被当成多句）或 JSON 不合法，temperature=0 下重试三次结果相同，125 个任务失败 5 个 | 句子改用「【句 i】」编号；重试时把上一次的错误告诉它；失败的任务排除出分母并单独计数，不当成通过。改后 dev、test 共 333 个评审任务零失败 |
| 14 | 阶段 2 | 模型别名已经变了 | 探测工具调用时，接口返回的 model 字段是 deepseek-flash 而不是 config 里的 deepseek-chat。查 DeepSeek 文档：deepseek-chat / deepseek-reasoner 两个旧名 2026-04-24 公告「三个月后停用」，当时分别指向 deepseek-v4-flash 的非思考 / 思考模式；2026-09-10 V4.1-Flash 发布后新名为 deepseek-flash，旧名到 09-30 仍可调用 | config 里写的模型名不等于实际服务的模型。Agent 模式的 done 事件与评测记录已保存接口返回的模型名；换模型名要当作系统改动，单独跑一次评测 |
| 15 | 阶段 2 | 工具缺单位，模型换了一个错的单位 | 试问「Wilo-WR 管径 200mm 时允许的力矩 Mz 换算成 N·m」（表中 85，单位 daN·m）：换算工具不认识 daN·m 报错，模型改用 kgf·m 重试，答出「85 daN·m = 85 kgf·m = 833.6 N·m」，正确是 850 N·m。工具算得没错，错在模型交给它的单位 | 确定性工具只保证「把被要求的算对」，参数仍由模型给出；工具报错时模型会找一个看似接近的替代。补齐了 daN·m、kN·m 等单位；后续校验器要核对「换算前的单位与原文是否一致」 |
| 16 | 阶段 2 | 限值先换算再核对被拒 | 模型把手册限值 4 L/min 先换算成 0.24 m³/h 再交给 check_value，工具在原文里找不到 0.24 而报错；模型改传原文数值与单位后通过，但多用了一轮工具调用 | 「限值数字必须出自所引片段原文」这条约束挡住了模型自己算出来的限值；参数说明改成「照抄原文的数值和单位，由工具换算」 |
| 17 | 评测 | 事实正则漏了正确写法 | Agent 多步任务集上，基线 dev 的「折合每分钟约 3.33 升」被判为没答出 3.33 L/min——模式要求数字后紧跟 L/min | 新写的事实模式要拿真实答案过一遍（在 dev 上做），修正后两个系统一起重评；修正只放宽等价写法（「3.33 升」「华氏 167 度」），不涉及对错标准 |
| 18 | 评测 | 换算句被判引用不成立 | Agent 按要求给「0.20 m³/h = 3.33 L/min」标原始数值所在的片段，评审只把计算输出 calc_1 列为依据，代码据此判这句引用不成立（任务集 dev 5/37）；答案把工具精确值 3.333 再舍入成 3.33，又被判为数字找不到出处 | 依据是工具输出时，由代码核对所标片段是否为限值出处、或含被换算的原始数值；带小数的数是工具精确值的正确舍入也算可溯源。只影响带工具输出的答案，基线用 --reuse 复算后分数不变 |
| 19 | 阶段 2 | 带引用的拒答 | 主集「Wilo-WR 配用电机的绝缘等级」「额定转速」「减速机齿轮箱换油」和任务集「D 型泵的机械密封泄漏量」4 题，Agent 都以「知识库无相关内容」开头并说明查到的内容为何不适用，但违反提示词带上了所查片段的编号，按阶段 1 的规则（拒答话术且不带引用才算拒答）记为作答，拒答召回 dev 15/15→13/15 | 规则没有在看到结果后修改，如实报告并在文档里写明这 4 题的实际内容；产品上以拒答话术开头的回答应按拒答展示，留到第 8 条校验器一并处理 |
