# 答案级评测：方法与结果

此前的评测只回答两个问题：正确的片段有没有被检索到（`eval/reports/s3_*`），以及答案里每句话有没有标引用（`eval/halluc_ab`）。都不涉及「答得对不对」。这份文档说明后来补上的答案级评测：评什么、怎么评、结果是什么、哪些结论还不能下。

- 评测集：[`eval/answer_set.yaml`](../eval/answer_set.yaml)（150 题，阶段 1）；[`eval/agent_tasks.yaml`](../eval/agent_tasks.yaml)（Agent 多步任务集 31 题，阶段 2）
- 脚本：[`src/answer_eval/`](../src/answer_eval/)，一条命令 `python src/answer_eval/run.py`
- 基线报告（rag 模式，阶段 1）：[`eval/answer_eval/baseline/report.md`](../eval/answer_eval/baseline/report.md)
- Agent 报告（阶段 2）：[`eval/answer_eval/agent_v1/report.md`](../eval/answer_eval/agent_v1/report.md)、
  [任务集](../eval/answer_eval/agent_v1/tasks/report.md)；并排对比 [`compare_baseline_vs_agent_v1.md`](../eval/answer_eval/compare_baseline_vs_agent_v1.md)；
  设计与结果解读见 [`docs/agent.md`](agent.md)

## 评测集

| 题型 | 题数 | 说明 |
|---|---|---|
| 正文事实 | 52 | 参数、限值、要求，多数带数值 |
| 操作步骤 | 11 | 停泵、灌泵、更换填料等 |
| 表格查询 | 29 | 故障表、参数表、零件清单、材料表 |
| 跨片段 | 9 | 答案需要两个片段，其中 1 题跨两份手册 |
| 口语化 | 10 | 「抖得厉害」「咋整」这类说法，与原文字面重合少 |
| 多轮追问 | 10 | 带前文，问句本身不完整（「MX 组呢？」），另附改写成独立问题的版本 |
| 相近领域（库外） | 14 | 空压机、减速机、变频器等，语料里没有 |
| 手册未写 | 9 | 与这些泵有关但手册没写（保修期、价格、噪声限值）；含 2 道跨手册陷阱 |
| 无关问题 | 6 | 天气、写诗、报税 |

前 6 类（121 题）应当作答，后 3 类（29 题）应当拒答或说明资料不足。四份手册的题数为 22 / 29 / 12 / 57，另有 1 题跨手册。

**怎么来的。** 由 Claude 通读四份手册的解析文本后逐条编写，没有用被测模型出题。旧评测集（`qa_set.jsonl`，36 题）是让 DeepSeek 对着某个片段出题，问句和原文字面重合偏高；而且拒答阈值 τ 就是在那 36 题上标定的，拿它测不出误拒率。新题全部重写，不复用旧问句。

**每道题标了什么。** 参考答案、关键事实、证据。
- 关键事实写成正则，作用在归一化后的答案上（全角转半角、去空白、℃→°c、m³→m3）。数值用带边界的匹配：`{n:0.1}` 匹配 0.1 和 0.10，不匹配 0.15 或 10.1。
- 证据写的是手册原文里的一段话，不是 chunk_id。评测时把引文解析成「包含这段话的片段」，以后改切分策略，评测集不会失效。

**校验。** [`validate.py`](../src/answer_eval/validate.py) 逐题检查：证据引文能在对应手册里找到；数值事实的数字确实出现在证据片段里；参考答案满足自己的关键事实；应拒答题声明「语料里没有」的词确实没有。评测前必须通过。校验器本身用 10 种故意改坏的题测过，全部能查出。

**dev / test。** 按题型分层、层内按手册和 id 哈希交替分配，dev 77 题、test 73 题，写入 `eval/answer_set_split.json` 后冻结。评测脚本的调试（切句、引用解析、评审提示词）只看 dev；test 在脚本定稿后只跑了一次。后续迭代系统也应只看 dev，test 只用来报数。

**尚未做的。** 评测集还没有经过人工逐条复核。

## 被测系统怎么调用

评测直接驱动 `src/s5_app/api.py` 的 `_sse_events`——FastAPI 接口背后的事件生成器，不经 HTTP。检索、拒答闸、提示词、生成参数、工具调用与线上同一条代码路径。系统的输出（答案、检索到的片段、工具调用步骤、token、耗时）落盘在 `answers.jsonl`，带系统指纹（模式、模型、提示词、参数、语料、流水线源码的哈希）；指纹变了就不会复用旧答案，也不允许覆盖同名的评测结果。

被测系统有两种模式（`--mode`）：`rag` 是阶段 1 的固定流水线，`agent` 是阶段 2 的工具调用 Agent。多轮题在 rag 模式下只发最后一句（它不看历史）；agent 模式把前文历史一起发。两种模式都另用改写后的独立问题再问一次，作为「追问被完美改写」时的参考。

流水线代码改过之后，旧评测仍可用 `--reuse`（系统输出与评审都只用缓存）或 `--frozen`（系统输出只用缓存、评审照常调用）重出报告：这时系统身份以评测目录里的 `system.json` 为准，不按当前代码重算指纹。

## 指标

确定性代码判定的：

| 指标 | 定义 |
|---|---|
| 证据全部召回 | 送入模型的前 k 个片段里包含了答案所需的全部证据 |
| 误拒 | 应作答的题被拒答闸拦截，或模型只回了拒答话术 |
| 关键事实召回 / 完全答对 | 关键事实被答出的比例 / 全部答出的题的比例 |
| 数值事实答对 | 关键事实里的数值部分 |
| 拒答召回 / 精确率 | 应拒答的题有多少被拒 / 被拒的题里有多少确实该拒 |
| 串手册 | 作答了，但引用的片段没有一个出自题目问的那份手册 |
| 无引用句占比 | 实质性句子里没有标引用的比例 |
| 数字可溯源 | 答案里的每个数字是否出现在检索片段、问句或换算/核对工具的输出里（带小数的数是工具精确值的正确舍入也算） |
| 字面重合度 | 句子的 4 字片段有多大比例原样出现在检索片段里 |
| 单题成本 | token × 单价（`config llm_pricing`）；两种模式都给「输入全按未命中计」的上限，agent 模式另给按接口返回的缓存命中计算的值 |
| 模型调用次数、工具用法 | agent 模式：每题几次模型调用、用了哪些工具、工具报错与达到轮数上限的次数；任务集另统计「期望的工具都用到了」（只作参考） |

数值是否答对、数字是否有出处，全部由代码判定，不交给模型。

评审模型判定的（逐句）：这句话有没有检索片段作依据（full / partial / none）、它标的引用是否确实支持它。Agent 的换算、核对输出以 `calc_1`、`calc_2`… 的编号和手册片段一起给评审；依据是工具输出的句子，「引用成立」由代码核对：所标片段须是核对的限值出处，或含有被换算的原始数值。

### 对评审模型的约束

评审模型和生成模型是同一个（deepseek-chat），不能直接信。做了四件事：

1. **摘抄核对。** 评审每判一句「有依据」，必须摘抄一段原文；代码核对这段话确实在片段里（忽略标点和空白）。对不上的不计入严格忠实度。
2. **与确定性结果对照。** 关键事实同时用正则和评审判，两者不一致的条目单列。基线里 193 条事实（dev 100 + test 93）全部一致。
3. **失败不算通过。** 输出不是合法 JSON、句数对不上，按失败计并排除出分母。
4. **灵敏度测试。** 往 dev 答案里注入已知错误，看它能不能查出来（[`probe.py`](../src/answer_eval/probe.py)）：

| 注入的错误 | 样本 | 检出 |
|---|---|---|
| 把一个数字改成片段里没有的数 | 40 | 40 |
| 把关键词换成反义词（关闭↔打开 等） | 30 | 29 |
| 追加一句手册里没有的操作要求 | 52 | 52 |

漏掉的 1 条是篡改本身没有意义（「启动和停止」被换成「停止和停止」）。确定性的数值溯源规则对改数字的检出是 40/40。

这说明评审对明显的错误是敏感的；它对真实答案里更隐蔽的错误是否同样敏感，要靠人工校准来回答。`calibrate.py export` 已导出 50 句 + 50 条事实的待标注样本，**人工判定尚未填写**。

## 基线结果

被测系统：deepseek-chat，C 组提示词，top_k=5，max_tokens=1024，τ=0.3567。方括号是 Wilson 95% 置信区间。

| | dev（77 题） | test（73 题） |
|---|---|---|
| **应作答的题** | 62 | 59 |
| 完全答对 | 0.790（49/62）[0.67, 0.87] | 0.729（43/59）[0.60, 0.83] |
| 误拒 | 0.161（10/62） | 0.237（14/59） |
| 　其中拒答闸 / 模型自述 | 9 / 1 | 10 / 4 |
| 证据全部召回 | 0.887（55/62） | 0.898（53/59） |
| 数值事实答对 | 0.897（35/39） | 0.914（32/35） |
| 实际作答的题的关键事实召回 | 0.940（94/100） | 0.957（89/93） |
| **应拒答的题** | 15 | 14 |
| 拒答召回 | 1.000（15/15） | 0.929（13/14） |
| 　其中拒答闸 / 模型自述 | 9 / 6 | 8 / 5 |
| **实际作答的答案** | 52 | 46 |
| 忠实度（严格） | 1.000（101/101 句） | 0.973（71/73 句） |
| 引用成立 | 1.000（95/95） | 0.986（72/73） |
| 无引用句占比 | 0.059（6/102） | 0.014（1/74） |
| 数字可溯源 | 0.993（137/138） | 1.000（103/103） |
| 作答耗时 P50 / P95 | 1795 / 2109 ms | 2052 / 4506 ms |

按题型的完全答对（dev / test）：正文事实 25/26、25/26；操作步骤 5/6、3/5；表格查询 14/15、9/14；跨片段 4/5、3/4；口语化 1/5、3/5；多轮追问 0/5、0/5。

### 读这组数字

**1. 生成不是瓶颈，瓶颈在它前面。** 证据全部召回、并且系统作答了的题，全部完全答对（dev 49/49，test 43/43）。证据没召回全却作答了的题，一道都没有完全答对（dev 0/3，test 0/2）。

**2. 拒答闸误拒是最大的失分项。** 证据已经全部召回、却没有作答的题，dev 6 道、test 10 道，全部是被拒答闸拦掉的。单轮问题里被闸误拒的是 dev 4/57、test 5/54；这 9 题里有 8 题的闸距离在 0.36–0.40 之间，只比 τ=0.3567 高一点（如「Wilo-WR 更换填料的操作步骤是什么？」0.3636）。τ 当初是在旧评测集上取的 P95，那上面的「误拒 5.6%」是定义使然；这里才是独立测得的数字。

**3. 多轮追问完全不可用。** 10 道追问全部被拒答闸拦截（问句不完整，向量距离 0.38–0.54）。把同样的问题改写成独立问句后，完全答对 dev 4/5、test 3/5——追问改写能解决大半，但剩下的仍会撞上拒答闸或检索失败。

**4. 检索没找到证据时，模型多数会如实说资料不足。** 模型自述拒答的 5 道应答题（dev 1、test 4），证据都没被检索到。这比编造好，但答不出。D 型泵手册最弱（test 5/9）：它的片段文本里不带手册名，问「D型泵…」时检索到的常是别的手册。

**5. 拒答并不全靠拒答闸。** 29 道应拒答的题里有 12 道的距离低于 τ、穿过了闸，其中 11 道被模型自己拒掉。漏掉的 1 道是「减速机齿轮箱的润滑油多久更换一次？」：系统用 Model 3700 泵手册的「每 3 个月（2000 运行小时）」作答。这句话相对检索片段是「有依据」的，评审也判为有依据——但它答的是另一种设备。

**6. 忠实度高是因为答案基本在摘抄原文。** 句子与检索片段的字面重合度中位数 0.87（dev）/ 0.84（test）。test 里唯一被判为无依据的句子是模型在说明「检索内容不足」，不是编造。所以这套系统当前的风险不是编造句子，而是**把对的内容安到错的对象上**（串设备、串手册），以及该答的不答。

## Agent 多步任务集（阶段 2）

主评测集考的是「把原文找出来、说对」。阶段 2 的 Agent 还要做「查到之后再加工」：换算单位、拿实测值和手册限值比、在大表里按行查。为此另建了 31 题的任务集（`eval/agent_tasks.yaml`，dev 17 / test 14，划分在 `eval/agent_tasks_split.json`）：

| 题型 | 题数 | 例子 |
|---|---|---|
| 单位换算 | 8 | 「Wilo-WR 出水管路名义直径 150 时轴封水量是多少？折合每分钟多少升？」 |
| 限值核对 | 8 | 「D 型泵运行中测得轴承温度 78℃，是否超过手册规定？」 |
| 表格精确查询 | 7 | 「Model 3700 的泵轴对应的零件编号是多少？」（旧检索评测里三种检索方式都找不到的 qa_038 同类题） |
| 多步 / 跨手册 | 5 | 「D 型泵和 Model 3700 对轴承温度的上限分别是多少？哪一个更高？」 |
| 手册没写的参数 | 3 | 「Wilo-WR 测得振动速度 4.5 mm/s，是否超出手册允许值？」（手册没有振动限值，不能编一个来比） |

两处扩展：

- **推算数值事实**：换算结果不在手册原文里，没法做「数字出自证据」的检查。这类事实写 `calc` 算式（如 `'0.2*1000/60'`），`validate.py` 核对模式里每个期望数字都是算式结果的正确舍入（3.33、3.3、3.333 都算 10/3 的正确舍入，3.34 不算）。换算系数在评测集里另写一遍，不依赖 Agent 的换算工具。
- **结论用语**：限值核对题的「超出 / 合格」用正则判断，带否定前缀的「未超过」「不应超过」、问句式的「是否合格」都不算（`selfcheck.py` 里有专门的自检）。

任务集在动 Agent 代码之前写好，并先用阶段 1 的系统生成了基线答案。用法：`run.py --set tasks`，结果在 `eval/answer_eval/<评测名>/tasks/`。

## 阶段 2：Agent 的结果

被测系统：工具调用 Agent（`src/s4_agent/agent.py`，设计见 [`docs/agent.md`](agent.md)），同一个模型，系统指纹 `a62c1e9b641a`。dev 上跑一次，只修了评测脚本自己的两处问题（事实正则漏了「3.33 升」这类写法；换算句的引用核对），没有改系统；test 只跑一次。

要点（详见 `docs/agent.md` 第 5 节）：误拒归零、多轮追问 10/10、数值事实全对，对应阶段 1 找出的三类失分；拒答召回按规则下降的 4 题，回答实际都以「知识库无相关内容」开头说明查不到，只是带上了所查片段的编号；无引用句上升主要来自 Markdown 表格行；代价是输入 token 约 3.5–5.6 倍、成本约 4.5–6.4 倍，任务集上慢约 1.8 秒。

关键事实的正则与评审对 Agent 答案的判断完全一致（主集 dev 126/126、test 129/129，任务集 dev 38/38、test 31/31），评审任务零失败。

## 不能下的结论

- 评测集未经人工复核；评审模型未经人工校准。上面的忠实度是「评审口径 + 摘抄核对」，不是人工结论。
- Agent 任务集针对的正是 Agent 新增的能力，基线在上面吃亏是设计使然；它说明的是新能力可靠不可靠，不是两个系统的综合优劣。
- 换算题的期望数字接受任意位数的正确舍入，包括取整：基线把 0.2 MPa 写成「2 kgf/cm²（按 1 MPa≈10 kgf/cm² 换算）」，正则按 2.04 的取整算答对，评审判为与参考答案矛盾。这是两者在任务集上仅有的 2 处分歧之一。
- 每个划分只有 60 题左右的应答题，置信区间宽：dev 0.790 与 test 0.729 的差别落在区间之内，不能说 test 更难。题型分组里多数只有 5–15 题，只能看方向。
- 单次运行、temperature=0，没有重复采样。
- 关键事实的正则是照着手册原文写的，模型换个说法可能漏判。基线里它与评审模型没有分歧，但系统改成会改写、会归纳之后，这一点要重新看。
- 「拒答」按「命中拒答话术且没有引用」判定。带着引用说「片段里没有这项内容」的回答算作答（test 有 1 道）。
